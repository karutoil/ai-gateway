## 1. Spend tracking

### 1.1 What is tracked per request — DB table `LiteLLM_SpendLogs`

One row per request, primary key `request_id`. Exact schema ([schema.prisma, `model LiteLLM_SpendLogs`](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/schema.prisma)):

| Column | Type | Meaning |
|---|---|---|
| `request_id` | String @id | LiteLLM call id |
| `call_type` | String | e.g. `acompletion`, `aembedding`, `aimage_generation` |
| `api_key` | String | **Hashed** virtual key (equivalent to `token` in `LiteLLM_VerificationToken`), never the raw key |
| `spend` | Float | computed USD cost |
| `total_tokens` / `prompt_tokens` / `completion_tokens` | Int | token counts |
| `startTime` / `endTime` | DateTime | both indexed (`@@index([startTime])`, `@@index([startTime, request_id])`) |
| `request_duration_ms` | Int? | wall time |
| `completionStartTime` | DateTime? | time-to-first-token anchor |
| `model` | String | reconstructed model name |
| `model_id` | String? | deployment id (unique per deployment, autogenerated) |
| `model_group` | String? | public `model_name` / model group |
| `custom_llm_provider` | String? | e.g. `openai`, `azure`, `vertex_ai` |
| `api_base` | String? | upstream base URL |
| `user` | String? | internal user id (`user_api_key_user_id`) |
| `metadata` | Json | standard logging metadata; also where `project_id` is stored |
| `cache_hit` | String? | `"True"`/`"False"` — LiteLLM **response-cache** hit |
| `cache_key` | String? | cache key used |
| `request_tags` | Json | `[]` by default |
| `team_id`, `organization_id`, `end_user` | String? | scoping dimensions (`end_user` is separately indexed) |
| `requester_ip_address` | String? | client IP |
| `messages`, `response` | Json | **only populated when prompt storage is enabled** |
| `session_id` | String? | indexed |
| `status` | String? | success/failure |
| `mcp_namespaced_tool_name` | String? | MCP tool attribution |
| `agent_id` | String? | A2A/agent attribution |
| `proxy_server_request` | Json | raw proxy-side request |

The writer builds exactly this object in `SpendLogsPayload(...)` — `spend=kwargs.get("response_cost", 0)`, `api_key=str(api_key)` (hashed), `user=metadata["user_api_key_user_id"]`, `team_id=metadata["user_api_key_team_id"]`, `organization_id=metadata["user_api_key_org_id"]`, `cache_hit=str(cache_hit)`, `end_user=end_user_id`, `custom_llm_provider=kwargs.get("custom_llm_provider")`, `session_id`, `agent_id`, `mcp_namespaced_tool_name`, `request_duration_ms` ([spend_tracking_utils.py L405-455](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/spend_tracking/spend_tracking_utils.py)). The `SpendLogsPayload` TypedDict is declared in [`litellm/proxy/_types.py` L3315+](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/_types.py).

`x-litellm-response-cost` is returned in response headers with the calculated cost ([cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking), [logging](https://docs.litellm.ai/docs/proxy/logging)).

### 1.2 Aggregate / rollup tables (this is what the analytics endpoints read)

Five daily aggregate tables, all with the same shape (per-day × api_key × model × provider × mcp tool × endpoint, `@@unique` on those), each carrying `spend`, `prompt_tokens`, `completion_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `compression_saved_tokens`, `compression_savings_spend`, `prompt_caching_savings_spend`, `api_requests`, `successful_requests`, `failed_requests` ([schema.prisma](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/schema.prisma)):

`LiteLLM_DailyUserSpend` · `LiteLLM_DailyTeamSpend` · `LiteLLM_DailyTagSpend` · `LiteLLM_DailyOrganizationSpend` · `LiteLLM_DailyEndUserSpend`

Related tables: `LiteLLM_ErrorLogs` (`request_id`, `startTime`, `endTime`, `api_base`, `model_group`, `litellm_model_name`, `model_id`, `request_kwargs`, `exception_type`, `exception_string`, `status_code`) and `LiteLLM_AuditLog` (`changed_by`, `changed_by_api_key`, `action`, `table_name`, `object_id`, `before_value`, `updated_values`) ([schema.prisma](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/schema.prisma)).

Balance/state tables: `LiteLLM_VerificationToken` (key `spend`, `max_budget`, `soft_budget`, `budget_duration`, `budget_reset_at`, `model_spend`, `model_max_budget`, `budget_limits`, `budget_fallbacks`, `budget_id`), `LiteLLM_TeamTable` (`spend`, `max_budget`, `soft_budget`, `budget_duration`, `budget_reset_at`, `model_spend`, `model_max_budget`, `budget_limits`), `LiteLLM_UserTable`, `LiteLLM_BudgetTable` (`max_budget`, `soft_budget`, `tpm_limit`, `rpm_limit`, `model_max_budget`, `budget_duration`, `budget_reset_at`, `allowed_models`), `LiteLLM_OrganizationTable`, `LiteLLM_TagTable` ([schema.prisma](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/schema.prisma)). `LiteLLM_BudgetTable` is the shared budget object related to organizations, projects, keys, end-users, tags, team memberships and organization memberships — the reason `/budget/new` budgets can be reused across entity types.

### 1.3 How cost is computed

- LiteLLM ships a model cost map and "automatically tracks spend for all known models" ([cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)); the map is [`model_prices_and_context_window.json`](https://github.com/BerriAI/litellm/blob/main/model_prices_and_context_window.json).
- Cost is **per-token**, not per-1M: keys are `input_cost_per_token` and `output_cost_per_token` ([custom_pricing](https://docs.litellm.ai/docs/proxy/custom_pricing)). There is **no** `input_cost_per_million_tokens` key — [UNVERIFIED] that such a key exists anywhere. Compute as `tokens × cost_per_token` (equivalently `$/1M ÷ 1e6`).
- Cache-aware pricing uses `cache_read_input_token_cost` and `cache_creation_input_token_cost` ([cost_calculator.py L200-222](https://github.com/BerriAI/litellm/blob/main/litellm/cost_calculator.py)); the custom-cost branch computes `prompt_tokens*input_cost_per_token + cached_tokens*cache_read_input_token_cost + cache_creation_tokens*cache_creation_input_token_cost` and `completion_tokens*output_cost_per_token`.
- Many additional cost keys are documented: `input_cost_per_token_above_200k_tokens`, `output_cost_per_token_above_200k_tokens`, `cache_creation_input_token_cost_above_200k_tokens`, `cache_read_input_token_cost_above_200k_token`, `input_cost_per_image`, `output_cost_per_reasoning_token`, `input_cost_per_audio_token`, `output_cost_per_audio_token`, `input_cost_per_video_per_second`, `input_cost_per_character`, `input_cost_per_token_priority`/`output_cost_per_token_priority`, `input_cost_per_token_flex`/`output_cost_per_token_flex`, `ocr_cost_per_page`/`annotation_cost_per_page`, `input_cost_per_second` (Sagemaker) ([custom_pricing](https://docs.litellm.ai/docs/proxy/custom_pricing)).
- Per-deployment override via `model_info` in `config.yaml`; `base_model` remaps the pricing lookup (needed for Azure and OpenAI dated-version responses) ([custom_pricing](https://docs.litellm.ai/docs/proxy/custom_pricing)).
- Tier-aware pricing is automatic when the response carries tier metadata: Vertex AI `usageMetadata.trafficType` (`ON_DEMAND_PRIORITY`→priority, `FLEX`/`BATCH`→flex) and Bedrock `serviceTier` ([cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking), [custom_pricing](https://docs.litellm.ai/docs/proxy/custom_pricing)).
- Zero-cost models: setting **both** `input_cost_per_token: 0` and `output_cost_per_token: 0` explicitly skips **all** budget checks (user, team, team member, end-user, organization, global proxy). Unset/`null` does **not** count as free ([custom_pricing](https://docs.litellm.ai/docs/proxy/custom_pricing)).
- Other cost transforms: [provider discounts](https://docs.litellm.ai/docs/proxy/provider_discounts), [provider margins](https://docs.litellm.ai/docs/proxy/provider_margins), [off-peak pricing](https://docs.litellm.ai/docs/proxy/off_peak_pricing), [Azure PTU flat cost attribution](https://docs.litellm.ai/docs/proxy/ptu_flat_cost). `cost_breakdown` exposes `input_cost`, `output_cost`, `total_cost`, `tool_usage_cost`, `original_cost`, `discount_percent`, `discount_amount`, `margin_percent`, `margin_fixed_amount`, `margin_total_amount` ([opentelemetry_integration](https://docs.litellm.ai/docs/observability/opentelemetry_integration)).

`$0`-priced requests that carried usage on a non-zero-rate model are still written with `spend = 0` and are flagged: one `WARNING` log naming the missing pricing key, plus the counter `litellm_zero_cost_requests_total` labelled `requested_model`, `model`, `model_id`, `api_provider`, `reason` (`missing_pricing_key` | `pricing_not_applied` | `cost_calculation_error`) ([cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking), [prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

### 1.4 Are streaming responses tracked?

**Yes.** The streaming path runs the success handler against the accumulated stream: `await self.async_success_handler(result=complete_streaming_response)` ([litellm_logging.py L1998](https://github.com/BerriAI/litellm/blob/main/litellm/litellm_core_utils/litellm_logging.py)) — so the full response (including `usage`) is priced and written. Supporting evidence: the writer explicitly handles "a request that failed mid-stream has no usable response_obj usage, but the streaming handler may have recovered the usage from the chunks already" ([spend_tracking_utils.py L273-274](https://github.com/BerriAI/litellm/blob/main/litellm/proxy/spend_tracking/spend_tracking_utils.py)); the Prometheus time-to-first-token histogram is documented as "Emitted only for streaming requests" ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

### 1.6 How request tags are attached

Four ways to set tags, in precedence order ([request_tags](https://docs.litellm.ai/docs/proxy/request_tags)):

1. Request body top-level `tags: [...]` — **wins over everything**
2. `x-litellm-tags: tag1,tag2,tag3` header (comma-separated, whitespace trimmed)
3. Body `metadata.tags: [...]` (must be an array of strings)
4. `litellm_params.tags` on the deployment in `config.yaml`

Header/body tags **override** model-config tags. Key- and team-level defaults come from `metadata.tags` on `/key/generate` or `/team/new`; [tag_budgets](https://docs.litellm.ai/docs/proxy/tag_budgets) additionally documents a **top-level** `tags` field on `/key/generate` and `/key/update`, and states a key-attached tag is enforced without clients passing `metadata.tags` per request. Additional header tags via `litellm_settings.extra_spend_tag_headers: ["x-custom-header", ...]`. User-Agent is tracked as a custom tag **by default** and can be turned off with `litellm_settings.disable_add_user_agent_to_request_tags: true` ([request_tags](https://docs.litellm.ai/docs/proxy/request_tags), [cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)).

### 2.2 `budget_duration` and resets

Format: seconds/minutes/hours/days, e.g. `"30s"`, `"30m"`, `"30h"`, `"30d"`; not set ⇒ budget never resets ([users](https://docs.litellm.ai/docs/proxy/users), [team_budgets](https://docs.litellm.ai/docs/proxy/team_budgets)).

| Duration | Default reset | Source |
|---|---|---|
| `1s`/`1m`/`1h`/`30m`/`10s` | rolls forward by interval from current time (time-of-day does not apply) | [budget_reset_and_tz](https://docs.litellm.ai/docs/proxy/budget_reset_and_tz) |
| `1d`/`24h` | daily at midnight (or `budget_reset_time`) | [budget_reset_and_tz](https://docs.litellm.ai/docs/proxy/budget_reset_and_tz) |
| `7d` | Monday at midnight | [budget_reset_and_tz](https://docs.litellm.ai/docs/proxy/budget_reset_and_tz) |
| `30d` | 1st of each month at midnight | [budget_reset_and_tz](https://docs.litellm.ai/docs/proxy/budget_reset_and_tz) |
| `1mo` | calendar month, 1st day | [users](https://docs.litellm.ai/docs/proxy/users) |

Multiple concurrent windows per key via `budget_limits` — `1h`=every hour, `24h`=daily midnight UTC, `7d`=Sunday midnight UTC, `30d`=1st of month midnight UTC ([users](https://docs.litellm.ai/docs/proxy/users)).

Timezone: `litellm_settings.timezone: "US/Eastern"` (any IANA string, `zoneinfo`-backed, DST-aware); default UTC. `litellm_settings.budget_reset_time: "09:00"` (`"HH:MM"` or `"HH:MM:SS"`, 24h, must be quoted) shifts day/week/month resets; malformed values **fail config load at startup**; sub-day durations ignore it ([budget_reset_and_tz](https://docs.litellm.ai/docs/proxy/budget_reset_and_tz)).

### 2.3 Soft vs hard budget, and what happens on exceed

| | `soft_budget` | `max_budget` |
|---|---|---|
| Effect | alert only — **never blocks requests** | hard limit — requests rejected |
| Delivery | email (SendGrid/Resend/SMTP required); deduped within 24h; checked on every request for key/team | error response |
| Config | `soft_budget` on key/team/customer/tag/budget; team recipients in `metadata.soft_budget_alerting_emails` (comma-separated) | `max_budget` |
| Source | [ui_team_soft_budget_alerts](https://docs.litellm.ai/docs/proxy/ui_team_soft_budget_alerts) | [users](https://docs.litellm.ai/docs/proxy/users) |

Errors on exceed (exact shapes observed in docs):
- Key: `{"detail":"Authentication Error, ExceededTokenBudget: Current spend for token: 7.2e-05; Max Budget for Token: 2e-07"}` ([users](https://docs.litellm.ai/docs/proxy/users))
- Team: `{"error":{"message":"Budget has been exceeded! Current cost: 3.5e-06, Max budget: 1e-09","type":"auth_error","param":null,"code":400}}` ([team_budgets](https://docs.litellm.ai/docs/proxy/team_budgets))
- Team member: `ExceededBudget: Crossed spend within team` ([users](https://docs.litellm.ai/docs/proxy/users))
- Per-model key: `{"type":"budget_exceeded","code":"400"}`, message `LiteLLM Virtual Key: <hash>, key_alias: None, exceeded budget for model=<model>` ([users](https://docs.litellm.ai/docs/proxy/users))
- Per-model user: `{"type":"budget_exceeded","code":"429"}` — note **429** here vs 400 elsewhere ([users](https://docs.litellm.ai/docs/proxy/users))
- Tag: `Budget has been exceeded! Tag=engineering Current cost: 505.50, Max budget: 500.0` ([tag_budgets](https://docs.litellm.ai/docs/proxy/tag_budgets))
- Global proxy / internal user: `ExceededBudget: User=<user_id> over budget. Spend=3.7e-05, Budget=0.0` ([users](https://docs.litellm.ai/docs/proxy/users))

Zero-cost models are skipped entirely for budget checks, so a free model can serve a budget-exhausted key ([users](https://docs.litellm.ai/docs/proxy/users)). Optional alternative to a hard stop: [budget fallbacks](https://docs.litellm.ai/docs/proxy/budget_fallbacks) route to another model.

**Existing spend counts against a budget added later.** A member who spent $500 with no budget, then given a $100 budget, is rejected on the next request. Escape only via a `budget_duration` reset or an explicit spend reset ([users](https://docs.litellm.ai/docs/proxy/users)).

### 2.4 Enforcement mechanics

- **Budget reservation is enabled by default.** LiteLLM estimates max cost from the body + model pricing, temporarily reserves it, rejects before calling the provider if the reservation would exceed budget, then replaces it with actual cost. Uses `max_tokens`/`max_completion_tokens` when present, else model limits. Routes without token pricing (some image/audio) cannot reserve and fall back to recorded spend. Disable with `general_settings.disable_budget_reservation: true` — a temporary mitigation, not a hardening step ([users](https://docs.litellm.ai/docs/proxy/users)).
- **Batch requests cannot be reserved** — `POST /batches` carries `input_file_id`, so the submission reservation is released and final cost recorded on completion ([users](https://docs.litellm.ai/docs/proxy/users)).
- **Hard fail-closed mode:** `general_settings.fail_closed_budget_enforcement: true` validates spend against the authoritative DB before admitting every budgeted request, covering **key, team, user, organization, end-user, tag, and per-window budgets**. If neither Redis nor DB can verify, the request is rejected with **503** ([users](https://docs.litellm.ai/docs/proxy/users)).
- **DB-less deployments enforce nothing.** Every budget on the page is enforced against spend read from the DB. `litellm_settings.max_budget` **fails open** there — the global check is skipped and requests are served past the limit, with a one-time startup warning. Key/team/user budgets are simply unavailable (`No connected db.`) ([users](https://docs.litellm.ai/docs/proxy/users)).
- Rate limits do **not** apply to proxy admin users ([users](https://docs.litellm.ai/docs/proxy/users)).

### 3.4 Customer / end-user

`POST /customer/new`, `POST /customer/update`, `GET /customer/info?end_user_id=`, `GET /customer/list`, `POST /customer/block`, `POST /customer/unblock`, `POST /customer/delete`; identical aliases at `/end_user/*`. Customer ID resolution order (first match wins): `x-litellm-customer-id` header → `x-litellm-end-user-id` header → custom header via `general_settings.user_header_mappings` → deprecated `user_header_name` → body `user` → `litellm_metadata.user` → `metadata.user_id` → `safety_identifier`. With JWT auth and `end_user_id_jwt_field`, the verified JWT claim beats all of these ([customers](https://docs.litellm.ai/docs/proxy/customers)).

Guard against junk customer IDs from agent clients (e.g. Claude Code puts a JSON blob in `metadata.user_id`): `litellm_settings.validate_end_user_id_in_db: true` (v1.87.0+) accepts an ID only if it matches an existing customer `user_id`, an internal user `user_id`, or an internal user email; JSON-shaped IDs are dropped before lookup (request still succeeds, spend attributed to key/team/user). Lookups cached 5 min on hit, 1 min on miss ([customers](https://docs.litellm.ai/docs/proxy/customers)).

**Customer budgets are global per deployment** — spend is tracked against the customer id alone, so one customer shares a single budget across every key and team, and a customer budget cannot be scoped to one key or team ([customers](https://docs.litellm.ai/docs/proxy/customers)).

`/customer/update` accepts only `user_id`, `alias`, `blocked`, `max_budget`, `budget_id`, `allowed_model_region`, `default_model`, `object_permission` — anything else (including `tpm_limit`, `rpm_limit`, `budget_duration`) is **silently dropped**; change those on the budget object with `/budget/update` ([customers](https://docs.litellm.ai/docs/proxy/customers)).

## 5. Prometheus metrics

### 5.1 Enabling

```yaml
litellm_settings:
  callbacks:
    - prometheus
```
`prometheus_client==0.20.0` needed for CLI installs (`uv add prometheus_client==0.20.0`); **already pre-installed in the litellm Docker image** ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

**Endpoint:** `GET /metrics` on the proxy port. **Authentication is required by default since v1.85.0** — either pass `Authorization: Bearer <key>` in the scrape config or set `litellm_settings.require_auth_for_metrics_endpoint: false` ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

**Dedicated metrics port (v1.101.0+):** `litellm --config config.yaml --num_workers 4 --prometheus_metrics_port 4001` or env `PROMETHEUS_METRICS_PORT`. Serves the same metric set from a separate process so scraping doesn't compete with inference. The old `/metrics` route stays for backward compat. **The dedicated listener does not use virtual-key auth** — `require_auth_for_metrics_endpoint` applies only to the proxy-port endpoint. Health: `GET :4001/health`; scrape `:4001/metrics/`. Helm: `metricsServer.{enabled,port}` + `serviceMonitor.enabled`; componentized chart: `gateway.metricsServer`; Terraform AWS: `gateway_metrics_port` + `gateway_metrics_scrape_cidrs` (module adds a nonessential sidecar; ALB does not route to it) ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

**Multiple workers:** set `PROMETHEUS_MULTIPROC_DIR` (e.g. `/prometheus_multiproc`) for aggregated collection across worker processes; the directory must exist and be writable ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)).

Status is typed for analytics: `status_fields.llm_api_status` ∈ success|failure and `status_fields.guardrail_status` ∈ success|guardrail_intervened|guardrail_failed_to_respond|not_run ([logging_spec](https://docs.litellm.ai/docs/proxy/logging_spec)). `metadata` carries `spend_logs_metadata`, `requester_custom_headers`, `applied_guardrails`, `usage_object`, `cold_storage_object_key`, `guardrail_information`, `attempted_fallbacks`, `original_model_group` ([logging_spec](https://docs.litellm.ai/docs/proxy/logging_spec), [cost_tracking](https://docs.litellm.ai/docs/proxy/cost_tracking)).

The standard payload also carries the full metadata map (`user_api_key_hash`, `user_api_key_alias`, `user_api_key_team_id`/`_alias`, `user_api_key_org_id`/`_alias`, `user_api_key_user_id`/`_email`, `user_api_key_end_user_id`, `user_api_key_project_id`/`_alias`, `user_api_key_spend`, `user_api_key_max_budget`, `user_api_key_budget_reset_at`, `user_api_key_request_route`, `requester_ip_address`, `user_agent`, `requester_metadata`, `requester_custom_headers`, `applied_guardrails`, `mcp_tool_call_metadata`, `vector_store_request_metadata`, `usage_object`, `spend_logs_metadata`, `cold_storage_object_key`, `user_api_key_auth_metadata`) plus `hidden_params` (`litellm_overhead_time_ms`, `api_base`, `response_cost`, `additional_headers`, `model_id`, `x-litellm-attempted-retries`, `x-litellm-attempted-fallbacks`) ([opentelemetry_integration](https://docs.litellm.ai/docs/observability/opentelemetry_integration)).

Cross-cutting controls: `x-litellm-call-id` response header for correlation; `turn_off_message_logging`; per-request `x-litellm-enable-message-redaction: true` / `LiteLLM-Disable-Message-Redaction: true`; `redact_user_api_key_info: true` (Langfuse, OpenTelemetry, Logfire, ArizeAI); `langfuse_default_tags` (choices: `cache_hit`, `cache_key`, `proxy_base_url`, `user_api_key_alias`, `user_api_key_user_id`, `user_api_key_user_email`, `user_api_key_team_alias`, `semantic-similarity`); `metadata.log_raw_request: true` to log the raw outbound curl ([logging](https://docs.litellm.ai/docs/proxy/logging)).

Delivery-failure monitoring: `litellm_callback_logging_failures_metric{callback_name}` for S3Logger, langfuse, and otel ([prometheus](https://docs.litellm.ai/docs/proxy/prometheus)). Enterprise adds **per-key / per-team callback routing** and management-op logs ([enterprise](https://docs.litellm.ai/docs/enterprise)).

## 8. OpenTelemetry

**Yes — LiteLLM emits OTLP traces, and optionally OTLP metrics and logs.** Enable with `litellm.callbacks = ["otel"]` / `litellm_settings.callbacks: ["otel"]`. Requires `opentelemetry-api opentelemetry-sdk opentelemetry-exporter-otlp` (and `grpcio` / `litellm[grpc]` for gRPC) ([opentelemetry_integration](https://docs.litellm.ai/docs/observability/opentelemetry_integration)).

**Destination config**

| Variable | Default | Purpose |
|---|---|---|
| `OTEL_EXPORTER` (alias `OTEL_EXPORTER_OTLP_PROTOCOL`) | `console` | `console`, `otlp_http`, `otlp_grpc`, `http/json`, `http/protobuf`, `grpc` |
| `OTEL_ENDPOINT` (alias `OTEL_EXPORTER_OTLP_ENDPOINT`) | none | OTLP endpoint URL (e.g. `http://0.0.0.0:4318`) |
| `OTEL_HEADERS` (alias `OTEL_EXPORTER_OTLP_HEADERS`) | none | `key=value,key2=value2` |
| `OTEL_SERVICE_NAME` | `litellm` | resource `service.name` |
| `OTEL_ENVIRONMENT_NAME` | `production` | resource `deployment.environment` |
| `OTEL_MODEL_ID` | `OTEL_SERVICE_NAME` | resource `model_id` |
| `OTEL_TRACER_NAME` / `LITELLM_METER_NAME` / `LITELLM_LOGGER_NAME` | `litellm` | tracer/meter/logger names |
| `OTEL_LOGS_EXPORTER` | none | logs exporter when events enabled |
| `SSL_CERT_FILE` / `litellm_settings.ssl_verify` | — | internal-CA support for `otlp_http`; SDK's `OTEL_EXPORTER_OTLP_CERTIFICATE` still wins |

**Toggles**

| Variable | Default | Effect |
|---|---|---|
| `LITELLM_OTEL_INTEGRATION_ENABLE_METRICS` | `false` | emit OTLP metrics |
| `LITELLM_OTEL_INTEGRATION_ENABLE_EVENTS` | `false` | emit OTLP semantic logs |
| `USE_OTEL_LITELLM_REQUEST_SPAN` | `false` | restore nested `litellm_request` span (since v1.81.0 the LLM attributes land on the proxy root span) |
| `OTEL_SEMCONV_STABILITY_OPT_IN` | unset | `gen_ai_latest_experimental` → latest GenAI semconv |
| `OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT` | unset | `NO_CONTENT` / `SPAN_ONLY` / `EVENT_ONLY` / `SPAN_AND_EVENT`; boolean form `true`→`EVENT_ONLY`, `false`→`NO_CONTENT` |
| `OTEL_IGNORE_CONTEXT_PROPAGATION` | `false` | ignore inbound `traceparent` |
| `OTEL_DEBUG` / `DEBUG_OTEL` | `false` | exporter diagnostics |
| `LITELLM_OTEL_V2` | unset | opt into the newer [OpenTelemetry v2](https://docs.litellm.ai/docs/observability/opentelemetry_v2) integration (one trace per request, HTTP → auth → guardrails → LLM → DB) |

**Span hierarchy:** root `Received Proxy Server Request` (`SERVER`) → optional `litellm_request` (`INTERNAL`) → `raw_gen_ai_request` (provider payload, `llm.{provider}.*`) and `guardrail`; plus service-hook spans `auth`, `router`, `self`, `proxy_pre_call`, `redis`, `postgres`, `batch_write_to_db`, `reset_budget_job`, `pod_lock_manager` (one span per `ServiceTypes` enum value, attributes `service`, `call_type`, optional `error`); `Failed Proxy Server Request` on exception; `{route}` spans for management endpoints. W3C `traceparent` is honored; parent resolution order is `metadata.litellm_parent_otel_span` → inbound `traceparent` (via `TraceContextTextMapPropagator`) → active span → none.

**OTLP metrics** (`enable_metrics=True`), named per GenAI semconv:

| Metric | Unit |
|---|---|
| `gen_ai.client.operation.duration` | `s` (includes LiteLLM overhead) |
| `gen_ai.client.response.duration` | `s` (LLM API generation only) |
| `gen_ai.client.token.usage` | `{token}` — two histograms per call, label `gen_ai.token.type` ∈ `input`/`output` |
| `gen_ai.usage.cost` | `USD` |
| `gen_ai.server.time_to_first_token` | `s` — streaming only |
| `gen_ai.server.time_per_output_token` | `s` |

Common labels: `gen_ai.operation.name`, `gen_ai.request.model`, `gen_ai.framework="litellm"`, plus `gen_ai.system` when the provider is known. **Renamed:** `gen_ai.usage.cost` ← `gen_ai.client.token.cost`; `gen_ai.server.time_to_first_token` ← `gen_ai.client.response.time_to_first_token`; `gen_ai.server.time_per_output_token` ← `gen_ai.client.response.time_per_output_token`.

**Events** (`enable_events=True`): `gen_ai.content.prompt` (one per input message), `gen_ai.content.completion` (one per choice); in semconv mode a single consolidated `gen_ai.client.inference.operation.details` carrying `gen_ai.input.messages` / `gen_ai.output.messages`.

**Cost attributes on spans:** `gen_ai.cost.input_cost`, `gen_ai.cost.output_cost`, `gen_ai.cost.total_cost`, `gen_ai.cost.tool_usage_cost`, `gen_ai.cost.original_cost`, `gen_ai.cost.discount_percent`, `gen_ai.cost.discount_amount`, `gen_ai.cost.margin_percent`, `gen_ai.cost.margin_fixed_amount`, `gen_ai.cost.margin_total_amount`. Correlation to spend logs via `litellm.call_id` + `litellm.request.type`; `llm.is_streaming`; `metadata.user_api_key_*` emitted on **both successful and failed** requests.

**Cardinality control** (metrics only; spans keep full attributes): `callback_settings.otel.attributes.{include_list|exclude_list}` (mutually exclusive; both ⇒ startup error). Valid names: `gen_ai.operation.name`, `gen_ai.system`, `gen_ai.request.model`, `gen_ai.framework`, `hidden_params`, and `metadata.{user_api_key_hash, user_api_key_alias, user_api_key_team_id, user_api_key_org_id, user_api_key_user_id, user_api_key_team_alias, user_api_key_user_email, user_api_key_end_user_id, spend_logs_metadata, requester_ip_address, requester_metadata, prompt_management_metadata, applied_guardrails, mcp_tool_call_metadata, vector_store_request_metadata}`. `gen_ai.token.type` **cannot** be filtered and is rejected in either list.

**Multiple handlers:** set `skip_set_global=True` on every handler past the first so each gets a private `TracerProvider`/`MeterProvider`/`LoggerProvider` ([opentelemetry_integration](https://docs.litellm.ai/docs/observability/opentelemetry_integration)).

**OpenTelemetry v2** (separate, opt-in): `LITELLM_OTEL_V2=true` produces "one clean trace per request" — `POST /v1/chat/completions` → `auth` (+ `postgres …` children) → `execute_guardrail <name>` → `chat <model>` → `batch_write_to_db` — using the same `OTEL_EXPORTER`/`OTEL_ENDPOINT`/`OTEL_HEADERS` env vars, with vendor presets as callbacks (`arize`, `arize_phoenix`, `langfuse_otel`, `weave_otel`, `langtrace`, `levo`, `agentops`). Prompts/responses are not captured unless explicitly opted in, and noisy routes (health, metrics scrapes, UI assets) are excluded automatically. Pick v1 **or** v2, not both ([opentelemetry_v2](https://docs.litellm.ai/docs/observability/opentelemetry_v2)).

**Trace propagation outbound:** `litellm_settings.forward_traceparent_to_llm_provider: True` forwards the inbound `traceparent` to self-hosted LLMs; the docs warn this can break Bedrock/Vertex AI ([logging](https://docs.litellm.ai/docs/proxy/logging)).

**`OTEL_TRACES_EXPORTER` is [UNVERIFIED]** — it is not documented on the OTEL page; the exporter variable there is `OTEL_EXPORTER` (alias `OTEL_EXPORTER_OTLP_PROTOCOL`), and `OTEL_LOGS_EXPORTER` exists only for logs.

**Backends documented:** Traceloop, Laminar, generic OTLP HTTP/gRPC collector, Splunk Observability Cloud, Jaeger, Zipkin, Datadog, New Relic, Levo AI, Arize, Phoenix, Langfuse, Weave.
